# 正式环境更新说明

> **用途**：系统进入正式运维后，区分「只改代码」和「要改数据库」时怎么上线。  
> **最后更新**：2026-10-22

正式环境的内容和代码是分开的。文章、栏目、单页正文、系统设置、菜单，在云主机后台修改，不用再同步回本地，也用不着 Git。Git 只管代码和模板。

本地数据库不再作为正式数据来源，不要用本地库覆盖云主机。

## 不改数据库结构

改的是 PHP、Blade、CSS 这类文件时：

1. 在本地改完后执行 `git commit`，再执行 `git push`。
2. 到云主机项目目录执行 `git pull`。
3. 如果改了页面模板，再执行：

```bash
"/c/php/php.exe" artisan view:clear
```

这类更新不会改动云主机上已经录入的文章和会员数据。

以下内容不在 Git 里，`git pull` 不会覆盖它们：

- `.env`
- 后台上传的图片、视频等文件（`storage` 下的上传目录）

## 要改数据库结构

加字段、加表、改字段类型时，在本地写 Laravel 迁移文件，和代码一起提交、推送。云主机 `git pull` 之后再执行：

```bash
"/c/php/php.exe" artisan migrate
```

`migrate` 只会执行还没跑过的新迁移，不会清空现有数据。

不要在云主机上执行 `migrate:fresh`。

如果一份迁移里还写了改栏目、改文章内容的语句，它在云主机上跑的时候会改正式数据。这种内容修改直接在云主机后台做，不要放进迁移。
